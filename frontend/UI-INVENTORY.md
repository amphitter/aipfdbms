# AIPF Frontend UI Inventory

Audited from `frontend/src`, `App.tsx`, `ui.tsx`, `styles.css`, and all TypeScript page modules.

## Global patient-selection refactor

- Shared component: `src/ui.tsx` → `PatientSearchSelect`.
- Server-backed endpoint: `GET /api/patients?q=...&limit=12`.
- Debounce: 240 ms; minimum query length: two characters; stale requests are cancelled or ignored.
- Integrated into New OPD/registration, billing counter, WhatsApp manual messaging, bed admission, and OT request workflows.
- Existing patient selection hydrates the editable Patient section. Patient edits use `PATCH /api/patients/:id`; the new visit uses the existing `/api/visits` operation and preserves the permanent Patient ID.
- Patient ID remains visible and searchable as a reference, but is no longer the primary selection input in these workflows.
- Snapshot review status: source/build validation completed; authenticated browser snapshots remain unavailable in the current tool environment and were not fabricated.

## Simplified OPD, consultation, prescription, and laboratory workflow

- Doctor queue now presents a compact list with one primary `CALL PATIENT` action and one `Open OPD` action.
- Consultation was rebuilt as one focused OPD workspace: patient header, one notes area, prescription section, lab request section, and one `COMPLETE OPD` action.
- Laboratory UI exposes only `PENDING`, `SAMPLE COLLECTED`, and `REPORT UPLOADED` to staff.
- Laboratory reports are uploaded manually as PDFs through `POST /api/lab/orders/:id/report-upload`, using the existing document storage and WhatsApp document provider paths. No report is generated by the simplified UI.
- Uploaded lab PDFs are linked to the patient, lab order, encounter, lab item, uploader, and timestamp, and are reused for view/download/WhatsApp actions.

## Shared interaction inventory

- Search: global search with Ctrl/Cmd+K and `/`; patients and billing have debounced search; documents and audit have local filters.
- Tables: shared `table.data` styling, sortable/filterable registry, operational tables across modules.
- Forms: shared `Field`, grid forms, inline filters, billing controls, master-data forms.
- Overlays: `Modal`, scanner sheet, user/notification popovers, tour spotlight, workflow training panel.
- Feedback: `Loading`, `Empty`, `ErrorState`, status pills, toast queue, permission guard.
- Confirmations: destructive browser confirmations remain in existing domain flows; transaction-sensitive medicine issue has explicit confirmation.
- Realtime: SSE in `App.tsx`; pages refresh selectively on relevant events. No one-second polling found. OT pairing uses interval-based status polling where the external pairing contract requires it.

## Refactor priorities

1. Strengthen the shared shell and common primitives first so every route gains consistency.
2. Preserve existing API contracts and permission checks.
3. Keep patient context and existing transactional billing/inventory behavior intact.
4. Replace only visual/interaction patterns that can be changed without inventing backend capabilities.
5. Treat the current TypeScript build errors as part of the refactor gate, while keeping unrelated domain behavior unchanged.

## Known backend/UI constraints

- No blood group or Aadhaar fields in the patient schema; show `—` and do not invent them.
- Beds are hospital capacity only when configured; sample beds are not capacity.
- WhatsApp is an external provider; UI reports provider state and never claims fake connectivity.
- Pharmacy medicine issue is intentionally performed through Billing; no separate invented dispense workflow is mounted.
- Global search uses the existing `/api/search` contract; missing entity types are not fabricated in the UI.
